Projects is the app for planning and tracking work in every Collabase Space. A project holds work items that move through the statuses of a workflow, and you decide per project which views and features its members see.

A Space can hold many projects. Each project has its own workflows, work item types, fields and members, and either all members of the Space can open it or only the people you add.

## Views

Each view is a tab in the project. A project admin switches tabs on and off under **Settings → Project features**; the order of tabs is fixed.

| View | Best for |
|---|---|
| **Home** | The project at a glance |
| **Board** | Moving work items between status columns |
| **Work Items** | Reviewing, filtering and editing many work items in a table |
| **Timeline** | Scheduling work items and dependencies on a calendar |
| **Backlog** | Ranking open work and planning it into cycles |
| **Time** | Time booked on the project's work items |
| **Mindmap** | The project's work items as a map |

**Cycles**, **Phases and gates**, **Risks** and **Costs** are features with their own switches in the same place. See [Project features](/projects/project-settings#features).

## Roles and access

A project either inherits its members from the Space or is **Private**, open only to the people you add, the Space owner and system administrators. Each member has one project role:

| Role | What it may do |
|---|---|
| **Manager** | Defined by the Space's [Permission Scheme](/concepts/permissions), typically managing the project's work and cycles |
| **Member** | Defined by the Permission Scheme, typically creating and updating work items |
| **Viewer** | Defined by the Permission Scheme, typically reading only |

Manage members and the access mode under **Settings → Team → Members**. Details: [Members and private projects](/projects/project-settings#private-projects).
