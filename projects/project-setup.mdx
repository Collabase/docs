This guide takes you from an empty instance to a project that a team can use on day one: its own fields, work item types, workflows and views, packed into a template. Follow the phases in order; each one builds on the previous one.

## At a glance

| | |
|---|---|
| **Result** | A published project template and a first project created from it |
| **Time** | About 45 minutes for a first template (an estimate), longer when you design several workflows |
| **You need** | A system administrator account with a second factor, and a Space where you may create projects |
| **Edition** | Every installation |

## Overview

| Phase | What you do | Time |
|---|---|---|
| [1. Fields](#phase-1-fields) | Create custom fields and group them into collections | 10 minutes |
| [2. Work item types](#phase-2-types) | Define the kinds of work | 5 minutes |
| [3. Workflows](#phase-3-workflows) | Design statuses and transitions | 15 minutes |
| [4. Template](#phase-4-template) | Bundle everything | 10 minutes |
| [5. Project](#phase-5-project) | Create the project and check it | 5 minutes |

## Phase 1: Fields {#phase-1-fields}

*Phase 1 of 5, about 10 minutes. Next: [Work item types](#phase-2-types).*

<Steps>
  <Step title="Create the fields">
    In **System Settings → Content & Organization → Custom Fields**, click **New Field** for each value the team must record, for example "Customer" as **Single choice**.
  </Step>
  <Step title="Group them">
    In **Field Collections**, click **New**, name the collection and add the fields. Click **Edit**, switch on **Work Items** under **Applies To**, and switch on **Show on Create** if members should fill them in right away.
  </Step>
</Steps>

<Check title="Checkpoint">
  The collection shows **Tasks** in the list and the fields under **Fields**. If a field is missing, see [Create a field collection](/admin/custom-fields#create-collection).
</Check>

**Next:** [Phase 2: Work item types](#phase-2-types)

## Phase 2: Work item types {#phase-2-types}

*Phase 2 of 5, about 5 minutes. Previous: [Fields](#phase-1-fields). Next: [Workflows](#phase-3-workflows).*

<Steps>
  <Step title="Create the types">
    In **Work Item Types**, click **New Work Item Type** for each kind of work, for example "Bug" and "Feature". Mark the most common one with **Set as default**.
  </Step>
  <Step title="Link type-specific fields (optional)">
    If a collection belongs to one type only, link that type to it under **Work Item Types** in the collection.
  </Step>
</Steps>

<Check title="Checkpoint">
  The **Work Item Types** list shows your types with their **Collections**. Details: [Work item types](/admin/work-item-types).
</Check>

**Next:** [Phase 3: Workflows](#phase-3-workflows)

## Phase 3: Workflows {#phase-3-workflows}

*Phase 3 of 5, about 15 minutes. Previous: [Work item types](#phase-2-types). Next: [Template](#phase-4-template).*

<Steps>
  <Step title="Create the workflow">
    In **Workflows**, click **New Workflow**, name it and click **Open Editor**.
  </Step>
  <Step title="Add statuses">
    Click **Add Status** for each status, starting with the one new work items should start in. Set the **Category** of each.
  </Step>
  <Step title="Draw transitions">
    Connect the statuses and name each transition. Add validators or transition fields where the process needs them.
  </Step>
</Steps>

<Check title="Checkpoint">
  The workflow card shows your statuses. If you plan a separate flow for one type, for example bugs, create that workflow too. Details: [Design workflows](/admin/workflows).
</Check>

**Next:** [Phase 4: Template](#phase-4-template)

## Phase 4: Template {#phase-4-template}

*Phase 4 of 5, about 10 minutes. Previous: [Workflows](#phase-3-workflows). Next: [Project](#phase-5-project).*

<Steps>
  <Step title="Create the template">
    In **Project Templates**, click **New Template**. Choose the views and features, add the workflows, map types to workflows, and select the work item types and field collections.
  </Step>
  <Step title="Publish it">
    Switch on **Published** and click **Create Template**.
  </Step>
</Steps>

<Check title="Checkpoint">
  The card under **Your templates** shows **Offered**. Details: [Project templates](/projects/templates).
</Check>

**Next:** [Phase 5: Project](#phase-5-project)

## Phase 5: Project {#phase-5-project}

*Phase 5 of 5, about 5 minutes. Previous: [Template](#phase-4-template).*

<Steps>
  <Step title="Create the project">
    In a Space, click **New Project**, choose your template under **Custom Templates** and click **Continue with** the template name.
  </Step>
  <Step title="Name it">
    Enter the **Project Name** and the **Project key**, the prefix of work item numbers, and click **Create Project**.
  </Step>
  <Step title="Check the settings">
    Collabase opens the project's **Settings** tab. **General** shows **Synced with template**. Under **Fields**, check that your collections are listed as assigned.
  </Step>
</Steps>

<Check title="Checkpoint">
  Create a work item of each type. The fields of your collections appear, and the status buttons follow your workflow. If fields are missing, see [Troubleshooting](#troubleshooting).
</Check>

## Keep it running

| What | When | Where |
|---|---|---|
| Template changes | Each save reaches linked projects | [Propagation](/projects/templates#propagation) |
| A team needs its own configuration | On request | [Detach a project](/projects/templates#detach) |
| A status is no longer used | When the process changes | [Delete statuses](/admin/workflows#delete) |

## Troubleshooting {#troubleshooting}

| Where | What you see | Cause | What to do |
|---|---|---|---|
| Work item | Custom fields are missing | **Work Items** is off on the collection, or the type is not linked | See [How fields reach a work item](/admin/custom-fields#how-fields-apply) |
| Project settings | **Fields** shows no assigned collection after creating the project | The collections reach linked projects with the next template save | Open the template, click **Edit Template** and save it once |
| New Project | The template is missing | It is not published | Switch on **Published** |
| Work item | Any status can be selected | No workflow applies | Add a workflow to the template or the project |
