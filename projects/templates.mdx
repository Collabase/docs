A project template is the starting configuration for new projects. It bundles workflows, work item types, field collections, the views a project shows, the fields a project must fill in and an optional phase model. Projects created from it stay linked, so a change to the template reaches them.

<WhoCanDoThis role="System administrator with a second factor set up" edition="Every installation" />

## System templates and your templates {#kinds}

**System Settings → Content & Organization → Project Templates** has two lists:

| List | Content |
|---|---|
| **System templates** | Shipped with Collabase and kept up to date, such as **HERMES klassisch** and **HERMES agil**. They cannot be edited. Switch off **Offer when creating a project** for the ones your organisation does not use. |
| **Your templates** | Templates your organisation defines and maintains. Each card shows **Offered** or **Hidden**. |

Templates are available in every Space.

## Create a template {#create}

Create the parts first: [workflows](/admin/workflows), [work item types](/admin/work-item-types) and [field collections](/admin/custom-fields). Then:

<Steps>
  <Step title="Start a template">
    Click **New Template**.
  </Step>
  <Step title="Fill in the editor">
    | Setting | Details |
    |---|---|
    | **Template Name** | With an icon picker. Up to 100 characters. |
    | **Description** | When to use the template. Up to 500 characters. |
    | **Published** | Published templates are visible in the project creation dialog. |
    | **Views & Apps** | The tabs a new project shows: **Home**, **List**, **Board**, **Backlog**, **Timeline**, **Time**, **Mindmap**, **Settings** |
    | **Features** | **Sprints**, **Story Points**, **Time Tracking** |
    | **Workflows** | Pick workflows with **Add Workflow**. The first one is the **Default**; change it with **Set as default**. |
    | **Workflow → Work Item Type Mapping** | Shown with two or more workflows. Assign types to a workflow; unmapped types use **Project default**. |
    | **Work Item Types** | The types the project offers |
    | **Field Collections** | The collections for work items |
  </Step>
  <Step title="Save">
    Click **Create Template**.
  </Step>
  <Step title="Add project fields and phases (optional)">
    Open the template again with **Edit Template**. Two more sections appear, each with its own save button:

    | Section | Details |
    |---|---|
    | **Project fields** | Fields a project fills in when it is created, shown in its settings and on its home tab. Add with **Add existing field** or **Create field**, mark them **Required**, then click **Save project fields**. Up to 30. |
    | **Phase model** | Phases with an optional **Gate**, **Gate criteria, one per line**, and **Milestones** as "name; days after project start". Click **Save phases**. Projects created later get these phases; existing projects keep their own copy. |
  </Step>
</Steps>

A new project gets everything the template carries in one step: its work item types, field collections, default workflow, views and features, and then its phases, quick filters and project home. If copying the phases, quick filters or home fails, the project is still created and you see a warning; add the missing part in the project settings.

Members choose the template in the first step of **New Project**, under **System Templates** or **Custom Templates**, then enter **Project Name** and **Project key** in **Project Details**.

## Linked projects and propagation {#propagation}

A project created from a template is linked to it. Its **Settings → General** shows **Synced with template**, and the sections **Project features**, **Status**, **Work Item Types** and **Fields** are read-only.

Every time you save a template, Collabase aligns the linked projects in the background. The template page shows the state under **Propagation to linked projects**: **Running**, **Up to date**, **Failed** or **Interrupted**, how many projects follow the template and how many were aligned.

| Part of the template | What linked projects get |
|---|---|
| **Views & Apps** | Exactly the template's list |
| **Default workflow** | The template's default. Work items whose status the new workflow does not have move to the first status of the same category. Work items of a type with its own workflow keep their status. |
| **Features** | The template's values. What a project remembers for itself, such as its board settings and cycle settings, stays. |
| **Field Collections** | Exactly the template's collections |
| **Work Item Types** | Exactly the template's types, in its order and with its default. A type the template drops is removed from a project when no work item has it, and phases out otherwise: the project keeps it for existing work items and no longer offers it for new ones. |
| **Project fields** | Read live from the template |
| **Phase model** | Not propagated |

Only one run per template is active at a time. If you save again while a run is going, the run continues with the new version. If a run is **Interrupted** or **Failed**, click **Propagate again**; projects that are already aligned are skipped. A project you detach during a run is left as it is.

## Detach a project {#detach}

Detach a project when its team needs its own configuration.

<Steps>
  <Step title="Open General">
    In the project, open **Settings → General**.
  </Step>
  <Step title="Detach">
    Click **Detach** and confirm with **Detach Project**. You see **Project successfully detached from template.**
  </Step>
</Steps>

<Warning>
  Detaching cannot be undone. The project keeps its current configuration, including its work item types and the project fields the template asked for, and no longer receives template changes. The audit log records who detached the project.
</Warning>

## Delete a template {#delete}

Click **Delete Template** on a card and confirm. The dialog names how many projects still follow the template. Those projects are detached: they keep their work item types, field collections, features, workflow and the project fields the template asked for, and no longer receive template changes. No new project can use the template. This cannot be undone. System templates cannot be deleted.

## Troubleshooting

| What you see | Cause | What to do |
|---|---|---|
| A template is missing in **New Project** | It is not **Published**, or a system template is switched off | Switch on **Published** or **Offer when creating a project** |
| A workflow is missing in **Add Workflow** | It does not exist yet | Create it in **Workflows** first |
| A linked project still has a removed collection | Propagation only adds | Detach the project and untick the collection under **Fields** |
