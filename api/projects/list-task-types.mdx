---
title: "List project work item types"
description: "The work item types a project offers, with its default and order."
api: "GET /api/v1/projects/{projectId}/task-types"
---

<Info>
  Scope `projects:read`. The key acts as the person who issued it: a project that person cannot reach answers `404`, and without the right to view the space the answer is `403`.
</Info>

## Query parameters {#query}

<ParamField query="includeRetired" type="string">
  `true` also lists types that are phasing out. Default `false`.
</ParamField>

## Response {#response}

<ResponseField name="data.items" type="object[]">
  One entry per offered type: `taskType` (`id`, `name`, `icon`, `color`), `isDefault`, `order` and `retiredAt`. A type that is phasing out has a `retiredAt`; work items that carry it keep it, new work items cannot use it.
</ResponseField>

<ResponseField name="data.configState" type="object">
  Whether the project follows a [project template](/projects/templates): `kind` is `linked`, `detached` or `none`. A project that follows a template cannot change its types. Guests do not get this field.
</ResponseField>

<RequestExample>

```bash cURL
curl "https://your-collabase.ch/api/v1/projects/clx0proj01/task-types" \
  -H "Authorization: Bearer cb_xYz123ABCD..."
```

</RequestExample>
