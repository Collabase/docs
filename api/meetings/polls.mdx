A poll starts as a `DRAFT` that only the meeting's organizers see. Opened, it is `OPEN` and takes
votes; closed, it is `CLOSED` for good and shows its result. Results are never visible while voting
runs, not even to the organizers. Votes themselves are cast in Collabase, not through the API.

## Poll types and answers

| `type` | Answers | Body fields |
|---|---|---|
| `YES_NO_ABSTAIN` | Fixed answers `yes`, `no`, `abstain` | none |
| `SINGLE_CHOICE` | Exactly one of the `choices` | `choices` |
| `MULTIPLE_CHOICE` | One or more of the `choices` | `choices` |
| `SCALE` | One whole number from `scale.min` to `scale.max` | `scale` |

Choices get the ids `c1`, `c2`, … in the order you send them. Tallies in the result use these ids,
the fixed answers, or the scale value as `key`.

## List a meeting's polls

`GET /api/v1/meetings/{meetingId}/polls` · scope `meetings:read`

Reading the polls closes any poll whose deadline has passed, so a result is never stale.

## Prepare a poll

`POST /api/v1/meetings/{meetingId}/polls` · scope `meetings:write` · `201`

Creates a draft. Organizers and co-organizers may do this, and participants too when the meeting
lets them record outcomes. The meeting must not be closed or cancelled.

<ParamField body="question" type="string" required>Up to 300 characters.</ParamField>
<ParamField body="type" type="string" required>`YES_NO_ABSTAIN`, `SINGLE_CHOICE`, `MULTIPLE_CHOICE` or `SCALE`.</ParamField>
<ParamField body="choices" type="string[] | null">For the two choice types: 2 to 12 distinct labels, each up to 200 characters.</ParamField>
<ParamField body="scale" type="object | null">For `SCALE`: `min` and `max` between 0 and 10 with `min` below `max`, plus optional `minLabel` and `maxLabel` of up to 60 characters.</ParamField>
<ParamField body="agendaItemId" type="string | null">The agenda item the poll belongs to. Must belong to this meeting.</ParamField>
<ParamField body="isAnonymous" type="boolean" default="false">Anonymous votes cannot be traced to a person once the poll is closed. Fixed when the poll opens.</ParamField>
<ParamField body="audience" type="string" default="INVITED">`INVITED` or `PRESENT`.</ParamField>
<ParamField body="closesAt" type="string | null">Deadline, ISO 8601. Must lie in the future. Voting ends at this moment without anyone closing the poll.</ParamField>

<RequestExample>

```bash cURL
curl -X POST https://collabase.example.com/api/v1/meetings/cm2…/polls \
  -H "Authorization: Bearer $COLLABASE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "question": "Where do we hold the offsite?", "type": "SINGLE_CHOICE", "choices": ["Bern", "Basel", "Chur"], "isAnonymous": true }'
```

</RequestExample>

{ "data": { "id": "cp4…" } }

## Change a draft

`PATCH /api/v1/meetings/{meetingId}/polls/{pollId}` · scope `meetings:write`

Send `baseUpdatedAt` plus any of the fields above. Fields you leave out keep their value; type,
choices and scale are checked again together. Only a `DRAFT` can be changed. If the poll was
changed or opened since you read it, the request returns `409 CONFLICT`; read it again.

## Open and close

| Method and path | Effect |
|---|---|
| `POST /api/v1/meetings/{meetingId}/polls/{pollId}/open` | Opens a draft for voting. The meeting must be planned or running, and a deadline must still lie ahead. |
| `POST /api/v1/meetings/{meetingId}/polls/{pollId}/close` | Ends voting now. The result becomes visible. |

Both need scope `meetings:write` and return `409 CONFLICT` when the poll is not in the state they
start from. A poll also closes on its deadline, and every open poll closes when the meeting ends or
is cancelled. A closed poll never reopens.

## Record the result as a decision

Pass the poll's `id` as `pollId` when you
[record a decision](/api/meetings/decisions#record-a-decision). The poll must be closed and belong
to the same meeting; each result can be recorded once. A second attempt returns `409 CONFLICT`.

## Anonymity

While an anonymous poll is open, a vote is stored under a key derived from the voter and a secret
of that poll, so the voter can change it. Closing deletes the secret. From then on no vote can be
traced to a person, not by the organizers or administrators. A database backup taken while the poll
was open still contains the secret, so treat backups as you treat the live data. Votes carry no
timestamps. With fewer than three votes, people in the room may still guess who voted
what; `isFewVotes` flags that case.
