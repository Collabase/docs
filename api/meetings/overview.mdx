The Meetings API gives integrations the same operations the Meetings app offers: create and plan
meetings, invite people, keep the agenda, run and close a meeting, and read or record its outcomes,
decisions and polls. Every call runs as the person who issued the token, with exactly the rights that
person has in Collabase.

## Meeting lifecycle

A meeting starts as a **draft** that only its organizers see in their calendar view.
[Planning](/api/meetings/lifecycle/plan-meeting) it sends the invitations. A planned meeting is
[started](/api/meetings/lifecycle/start-meeting) by a moderator, then
[closed](/api/meetings/lifecycle/close-meeting), which freezes it and queues the meeting note. A closed
meeting can be [reopened](/api/meetings/lifecycle/reopen-meeting) for a correction. Drafts and planned
meetings can be [cancelled](/api/meetings/lifecycle/cancel-meeting). A call in the wrong state, for
example starting a draft, returns `409 CONFLICT`.

| Status | Meaning |
|---|---|
| **`DRAFT`** | Created, not announced, no invitations sent |
| **`PLANNED`** | Announced; participants hold it in their calendar |
| **`RUNNING`** | In progress; outcomes and decisions can be recorded |
| **`CLOSED`** | Ended; read-only until reopened |
| **`CANCELLED`** | Called off; everyone who held it received a cancellation |

## Scopes

| Scope | Allows |
|---|---|
| `meetings:read` | Every `GET` endpoint below |
| `meetings:write` | Every other endpoint; includes `meetings:read` |

A token without the scope receives `403 INSUFFICIENT_SCOPE`. A token with the scope still cannot do
more than its owner: a person who may not edit a meeting gets `403 FORBIDDEN` through the API too.

## Conventions

- **Visibility.** A meeting the caller may not see answers `404 NOT_FOUND`, exactly like one that
  does not exist. Private meetings are visible only to their participants.
- **Times.** Instants in responses are ISO 8601 in UTC. When you create or move a meeting, `date`
  (`YYYY-MM-DD`) and `time` (`HH:mm`) are wall-clock values in the time zone of the token owner's
  profile, the same way the app reads them. Instants you send, such as `baseUpdatedAt` and a poll's
  `closesAt`, must be UTC with a `Z` (`2026-10-15T08:05:12.000Z`); an offset such as `+02:00` is
  rejected with `422`.
- **Concurrent edits.** Changes to agenda sections, agenda items, outcomes and decisions carry
  `baseUpdatedAt`, the `updatedAt` you read. If someone changed the object since, the request
  returns `409 CONFLICT` with the object as it is now in `current`, next to `error`. Re-read, merge
  and send again. Draft polls carry `baseUpdatedAt` as well; their conflict returns `409 CONFLICT`
  without `current`.
- **Strict bodies.** Unknown fields are rejected with `422 VALIDATION_ERROR`, not silently dropped.
  A missing or malformed JSON body answers `422` too, except on the endpoints whose body is optional
  ([Cancel meeting](/api/meetings/lifecycle/cancel-meeting), [Close meeting](/api/meetings/lifecycle/close-meeting)).
- **Limits.** A meeting holds up to 500 participants, 50 agenda sections, 200 agenda items, 500
  outcomes, 300 decisions and 50 polls. Going beyond answers `400 VALIDATION_ERROR`.
- **App switched off.** If the Meetings app is not enabled on the instance, every endpoint answers
  `404 NOT_FOUND`.

## Errors

On top of the [general errors](/api/introduction#response-format):

| Status | Code | Meaning |
|---|---|---|
| `400` | `VALIDATION_ERROR` | The request is well formed but does not fit the meeting, for example a decision maker who is not invited |
| `409` | `CONFLICT` | Someone changed the object since you read it, or the meeting is in the wrong state for this action |
| `409` | `MEETING_NOT_WRITABLE` | The meeting is closed or cancelled; reopen it first |
| `409` | `MEETING_NOT_RUNNING` | Outcomes and decisions are recorded only while the meeting runs |

```json 409
{
  "error": { "code": "CONFLICT", "message": "Changed by someone else since it was loaded" },
  "current": { "id": "cm4sect0001", "title": "Budget 2027", "order": 1000, "updatedAt": "2026-10-15T08:05:12.000Z" }
}
```

## Reacting to changes

There is no separate webhook subscription for meetings. Build an
[automation](/automation/triggers#collabase-events) on one of the meeting events (created, updated,
cancelled, closed, decision recorded, note published) and add an **HTTP** action that calls your
system. An event reaches only automations whose owner may see the meeting. It carries identifiers,
dates and a decision's title, never agenda text or notes; read the details through this API with a
token of your own.

The other direction works too: the Collabase connector has the automation actions **Create
Meeting**, **Add Agenda Item** (also to the next occurrence of a series) and **Invite to Meeting**,
which act with the automation owner's rights. See the
[Collabase connector](/automation/connectors/collabase).
