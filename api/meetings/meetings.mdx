A meeting starts as a **draft** that only its organizers see in their calendar. **Planning** it sends
the invitations. A planned meeting is **started** by a moderator, then **closed**, which freezes it
and queues the meeting note. A closed meeting can be **reopened** for a correction. Drafts and planned
meetings can be **cancelled**.

| Status | Meaning |
|---|---|
| `DRAFT` | Created, not announced, no invitations sent |
| `PLANNED` | Announced; participants hold it in their calendar |
| `RUNNING` | In progress; outcomes and decisions can be recorded |
| `CLOSED` | Ended; read-only until reopened |
| `CANCELLED` | Called off; everyone who held it received a cancellation |

## List your meetings

`GET /api/v1/meetings` · scope `meetings:read`

Returns meetings the token owner is invited to, not the ones they could merely read through a Space.

<ParamField query="view" type="string" default="upcoming">
  `today`, `upcoming`, `past` (newest first) or `series` (occurrences of series).
</ParamField>

<ParamField query="cursor" type="string">
  The `nextCursor` of the previous page. Pages hold up to 50 meetings.
</ParamField>

<ResponseField name="items" type="object[]" required>
  Meetings with `id`, `title`, `startsAt`, `durationMinutes`, `status`, `visibility`, `location`,
  `videoUrl`, `space`, `project` and the owner's `role`.
</ResponseField>

<ResponseField name="nextCursor" type="string | null" required>
  Pass it as `cursor` for the next page; `null` on the last page.
</ResponseField>

<ResponseField name="timezone" type="string" required>
  The token owner's time zone.
</ResponseField>

## Create a meeting

`POST /api/v1/meetings` · scope `meetings:write` · `201`

Creates a draft with the token owner as organizer. Plan it to send the invitations.

<ParamField body="title" type="string" required>Up to 200 characters.</ParamField>
<ParamField body="date" type="string" required>`YYYY-MM-DD` in the token owner's time zone.</ParamField>
<ParamField body="time" type="string" required>`HH:mm` in the token owner's time zone.</ParamField>
<ParamField body="durationMinutes" type="number" required>1 to 720.</ParamField>
<ParamField body="spaceId" type="string | null">Space the meeting belongs to. The owner needs to see the Space.</ParamField>
<ParamField body="projectId" type="string | null">Project within that Space.</ParamField>
<ParamField body="location" type="string | null">Up to 500 characters.</ParamField>
<ParamField body="videoUrl" type="string | null">An `http` or `https` link.</ParamField>
<ParamField body="visibility" type="string" default="STANDARD">`STANDARD` or `PRIVATE`. A private meeting is visible to its participants only.</ParamField>
<ParamField body="participantsMayEdit" type="boolean" default="false">Participants may edit the agenda and record outcomes, not only organizers.</ParamField>
<ParamField body="bufferPercent" type="number" default="0">Share of the duration kept free when planning the agenda, 0 to 50.</ParamField>
<ParamField body="submissionsToAgenda" type="boolean" default="false">Submitted topics go straight onto the agenda instead of waiting for review.</ParamField>
<ParamField body="submissionLeadHours" type="number | null" default="null">Topics are taken until this many hours before the start (1 to 336); `null` means until it starts.</ParamField>

<ResponseField name="id" type="string" required>The new meeting.</ResponseField>

<RequestExample>

```bash cURL
curl -X POST https://collabase.example.com/api/v1/meetings \
  -H "Authorization: Bearer $COLLABASE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "title": "Release planning", "date": "2026-10-15", "time": "10:00", "durationMinutes": 45, "spaceId": "cm1…" }'
```

</RequestExample>

<ResponseExample>

```json 201
{ "data": { "id": "cm2…" } }
```

</ResponseExample>

## Read, change or delete a meeting

`GET /api/v1/meetings/{meetingId}` · scope `meetings:read`

Returns the meeting with its organizer, the series it belongs to, the time zone it was planned in
(`meetingTimezone`) and what the token owner may do with it (`canEdit`, `canPlan`, `canCancel`,
`canStart`, `canReopen`, `canMakeSeries`).

`PATCH /api/v1/meetings/{meetingId}` · scope `meetings:write`

Takes the same fields as creating, all optional. `date` and `time` always travel together. A
planned meeting sends updated invitations after the change. Closed and cancelled meetings cannot be
changed (`409 MEETING_NOT_WRITABLE`).

`DELETE /api/v1/meetings/{meetingId}` · scope `meetings:write`

Deletes a draft or a cancelled one-off meeting. A meeting that reached anyone's calendar or holds
decisions stays; cancel it instead.

## Lifecycle

All lifecycle calls are `POST` with scope `meetings:write` and return `{ "data": { "id": "…" } }`.

| Path | Body | Effect |
|---|---|---|
| `/api/v1/meetings/{meetingId}/plan` | none | Draft to planned; the invitations go out shortly after |
| `/api/v1/meetings/{meetingId}/cancel` | `{ "reason": "…" }`, optional, up to 500 characters | Draft or planned to cancelled; the reason appears in the cancellation mail |
| `/api/v1/meetings/{meetingId}/start` | none | Planned to running; needs moderator rights |
| `/api/v1/meetings/{meetingId}/close` | `{ "carryItemIds": ["…"] }`, optional | Running to closed. In a series, `carryItemIds` names the open items handed on to the next occurrence; without it every open item is handed on |
| `/api/v1/meetings/{meetingId}/reopen` | none | Closed to running for a correction; recorded in the audit log |

A call in the wrong state, for example starting a draft, returns `409 CONFLICT`.
