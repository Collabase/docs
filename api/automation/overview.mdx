The Studio API lets an integration list Spaces, manage flows and start and follow runs. It is part of `/api/v1`, so it uses the same tokens, the same envelope and the same errors as the rest of the API.

## Authentication and scopes

Send the token as `Authorization: Bearer cb_...`. A token acts as the person who made it and can never do more than that person.

| Scope | Allows |
|---|---|
| `automation:read` | List Spaces, flows and runs, and read one of each. |
| `automation:write` | Create, rename, delete, publish and switch flows, start runs and retry runs. |

Without a scope the answer is `403 INSUFFICIENT_SCOPE`. An unknown or expired token gets `401`. A person with the viewer role gets `403` on every change, whatever the token's scope.

## Pagination

Lists answer `{ "data": { "items": [...], "nextCursor": "..." } }`. Send `nextCursor` as `cursor` for the next page. `limit` is at most 100. The cursor holds the position of the last item, so items that arrive between two requests never shift a page. A cursor that Collabase does not recognise answers `422`. Runs come newest first.

## Idempotent starts

Send an `Idempotency-Key` header, up to 200 printable characters, when you start a run. A repeat with the same key within 24 hours answers with the run of the first call and starts nothing. A call that arrives while the first is still being handled gets `409`.

## Errors

Errors use the envelope `{ "error": { "code": "...", "message": "..." } }`. Besides the common ones (`401`, `403`, `404`, `422`), these matter for Studio:

| Status | Meaning |
|---|---|
| `409` | An `Idempotency-Key` is still being handled, or the flow is not published (`FLOW_NOT_RUNNABLE`). |
| `413` | A body, a file or an upload is larger than allowed. |
| `415` | A file sent to a webhook has a kind that Collabase does not accept. |
| `429` | A webhook address got more than 120 calls a minute for one flow. `Retry-After` says how many seconds to wait. |

## What the API does not expose

Connection values, secret store settings, OAuth apps, members, the Git connection and the AI provider are not reachable through the API.

## Addresses without a token

Five addresses work without a token, because another system calls them: [the webhook address](/api/automation/call-webhook), [its synchronous variant](/api/automation/call-webhook-sync), [its test address](/api/automation/test-webhook), [the address of an app's events](/api/automation/app-events) and [the address of a waiting run](/api/automation/resume-run). The flow id or the token in the address is the credential, and a webhook trigger can ask for a login on top.
