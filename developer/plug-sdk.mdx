The Plug SDK is the way to add your own triggers and actions to Automation. A plug connects flows to a system that the catalog does not cover: your ERP, an internal service, a supplier's API.

<Note>
  The Plug SDK is published from **Q4 2026**, with the npm packages and the command line tool. The SDK, the tool and the example plugs are open source under the MIT licence. The built-in plugs and the engine are not. The guide below describes how plugs are built, tested and uploaded.
</Note>

## What you can build

- **Actions**, which flows run as steps: read an order, confirm a delivery, send a document.
- **Triggers**, which start flows: poll a system for new items, or register a webhook in it.
- **Authentication**, so that a person connects the plug once with a secret, a login or OAuth and flows use that connection.

A plug that Collabase did not write runs in a sandbox with no route to your internal systems and gets only the connection of the step that is running. See [Limits of the sandbox](/developer/plugs/sandbox).

## A first plug

```bash
collabase-plug init hello-plug --name hello-plug
cd hello-plug
collabase-plug build
COLLABASE_API_TOKEN=cb_... collabase-plug publish dist/hello-plug-0.1.0.tgz --url https://your-instance
```

The plug appears in the step list of the flow editor, marked as an own plug. [Get started](/developer/plugs/get-started) walks through it with the code.
