Collabase keeps every version of a flow that was published.

- A **draft** can be edited as often as you like.
- **Publishing** locks the draft as a version. A version never changes after that.
- Editing a published flow opens a new draft that copies the published version, if no draft exists.
- Because versions are locked, you can go back to an earlier one, edit it as a draft and leave the live version alone.

## Open the history

Select **Versions** in the editor. The list shows the published versions as **Version 1**, **Version 2** and so on, newest first, with the time and the person who published each one. The live one is marked **Published**.

## Look at a version

Select **View** on a version to open it **Read-only**, drawn like the flow. Nothing changes. Select **Use as draft** in that view to copy the version into the draft.

## Restore a version

An editor selects **Restore** on a version, or **Use as draft** in its view. Collabase asks **Replace the draft?** and says that changes in the draft that are not published are lost. When you confirm, the content of the version is copied into the draft. The published version does not change until you publish the draft. Restoring needs the editor lock, so another person's open draft is not overwritten without notice.

## See when the draft differs

While the draft differs from the published version, the toolbar shows **Draft differs from published**. It tells you that publishing would change the flow that runs.

## Discard the draft

When the flow has a published version, an editor can select **Discard draft** in the list of versions and confirm **Discard the draft?** The draft is reset to the published version and the unpublished changes are lost. Use it when you want to start again from what is live.

## One draft at a time

Only one person edits a draft. The editor shows who holds it. Another editor can **take over** after the holder's lock has expired, which happens 10 minutes after the last change. If the flow changed while you had it open, the editor asks you to **Reload** so you do not overwrite a change you did not see.

## Runs and versions

A run keeps the version it started with. When you [retry a run](/automation/debugging-runs#retry-a-run), you choose between the version the run used and the published version.

## Releases and Git

If the Space is connected to Git, a release records the state of the flows of the Space at one point, and a rollback applies an earlier state. See [Git sync and releases](/automation/git-sync).
