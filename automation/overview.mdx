Studio runs work you would otherwise do by hand. A flow starts from a trigger, such as a new work item, a call from another system or a time of day, and then runs its steps one after the other. Each step is an action of a plug: create a work item, send a notification, call another system, ask a person to approve, or let an AI agent reach a goal.

Studio was called Collabase Automation before.

## Why use Studio

<AccordionGroup>
  <Accordion title="One place for routine work">
    Flows live in automation workspaces that a team owns. The team sees every flow, every run and every change in one list, and a run that fails says which step failed and why.
  </Accordion>
  <Accordion title="Safe by design">
    A flow acts with the rights of its workspace's service account, never with more. Connection values are stored encrypted and never shown again. Plugs that Collabase did not write run in an isolated sandbox with no route to your internal systems.
  </Accordion>
  <Accordion title="People stay in control">
    A step can ask a named person to approve before the flow goes on. A sensitive workspace needs a second admin before a flow is published or switched on. An AI agent can be held to the same rule for each tool it uses.
  </Accordion>
  <Accordion title="Works without AI">
    Everything except the AI steps, building a step from a sentence and the Collabase AI tools works without an AI provider.
  </Accordion>
</AccordionGroup>

## Key concepts

| Concept | What it is |
|---|---|
| **Automation workspace** | A group of flows that a team manages together, with its own members, connections, runs, audit trail and analytics. |
| **Flow** | A trigger and the steps that follow. A flow has a draft you edit and a published version that runs. |
| **Plug** | A package that adds triggers and actions for an app or service. Collabase plugs come with the product. Core and community plugs are installed by an administrator. |
| **Connection** | The credentials a plug uses to reach another system. |
| **Run** | One execution of a flow, with the log of each step. |

## How to access Studio

<Steps>
  <Step title="Get the Studio right">
    An administrator gives you the **Studio** app right under **Administration, Users**. Anyone with the right can create an automation workspace.
  </Step>
  <Step title="Open Studio">
    Select **Studio** in the app drawer. A system administrator finds a default workspace already there.
  </Step>
  <Step title="Create a flow">
    Open a workspace, select **New flow** and build it in the editor, or start from a template or a file.
  </Step>
</Steps>

## What Studio is made of

| Part | What it does |
|---|---|
| **Flows** | A trigger and steps that run without anyone doing them by hand. [Building flows](/automation/building-flows) |
| **Agents** | A named assistant with an instruction, tools and knowledge, used in chats, flows and jobs. [Agents](/automation/agents) and the [Agent step](/automation/agent-step) |
| **Tables** | Rows of data that flows read and write, kept in the Registry. [Tables](/automation/tables) |
| **Plugs** | The triggers and actions for Collabase apps and other systems. [Plugs](/automation/plugs) |

They combine freely. An Agent step can start a flow as a tool, a flow can run an agent as a step, and both can read and write the same tables.
