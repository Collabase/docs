A work item type names a kind of work, such as **Bug**, **Feature** or **Change Request**. Members pick the type when they create a work item, and the type decides which [field collections](/admin/custom-fields) and which [workflow](/projects/workflows#mapping) apply to it.

<WhoCanDoThis role="System administrator with a second factor set up" edition="Every installation" />

## Where types come from {#where-types-come-from}

You define types once for the instance, or once for a space. A project **offers** a type when a project manager adds it in the project settings. Every project offers its own list, with its own order and its own default type. A type is never copied into a project: when you rename it or change its fields or workflow, every project that offers it shows the change.

A project that is created from a [project template](/projects/templates) starts with the types of the template. A project created without a template starts with the types of its kind, with **Task** as the default.

## Create a work item type {#create}

<Steps>
  <Step title="Open Work Item Types">
    Open **System Settings → Content & Organization → Work Item Types** and click **New Work Item Type**.
  </Step>
  <Step title="Fill in the panel">
    | Setting | Details |
    |---|---|
    | **Name** | Required, up to 60 characters. Shown on work item cards and in lists. A name is unique across the instance and all spaces, ignoring case and surrounding spaces. |
    | **Icon** | Pick one of the icons in the grid. |
    | **Description** | Optional. Explains when to use the type. |
    | **Set as default** | Used when no type is explicitly chosen. |
  </Step>
  <Step title="Save">
    Click **Save**. You see **Work item type created** and the type appears in the list.
  </Step>
</Steps>

The list shows each type's **Name**, **Description**, linked **Collections** and whether it is the **Default**. To make an existing type the default, hover over its row and click **Set as default**.

## Delete a work item type {#delete}

You can delete a type only while nothing uses it. If projects offer it, project templates list it or work items carry it, the deletion is refused and the message says how many projects, templates and work items depend on the type. Remove it from those projects and templates, or change the work items to another type, and try again. System types cannot be deleted. Deleting a type cannot be undone.

To stop a single project from offering a type, use **Remove** in the project's settings instead. See [Types in project settings](#project-types).

## Give a type its own fields {#fields-per-type}

Link field collections to a type on the collection, not on the type:

<Steps>
  <Step title="Open the collection">
    Open **System Settings → Content & Organization → Field Collections**, select the collection and click **Edit**.
  </Step>
  <Step title="Link the type">
    Under **Work Item Types**, pick the type in **Link work item type…**. The **Collections** column on the **Work Item Types** page shows the link.
  </Step>
</Steps>

A collection with no linked types applies to every type. Details: [How fields reach a work item](/admin/custom-fields#how-fields-apply).

## Give a type its own workflow {#workflow-per-type}

Each project, or each project template, maps work item types to workflows. A type without a mapping uses the project's default workflow. See [Workflows in a project](/projects/workflows#mapping).

## Types in project settings {#project-types}

A project's **Settings → Work Item Types** lists the types the project offers, in the order members see them. The default type is marked **Default**, a type that is being phased out **Phasing out**, and types of the instance carry the badge **Global**.

With **Manage project settings** you can:

- **Add** a type of the instance or of the space with **Add Work Item Type**. It appears at the end of the list.
- **Move** a type up or down, and **make it the default**, from the menu of its row. The default is the type a new work item gets when nobody picks one, for example from mail or an automation.
- **Remove** a type from the project. The type stays in the catalog. It cannot be removed while a work item of the project still has it (the message names how many), and a project keeps at least one type.

While the project is linked to a template, the section is read-only and says that the project follows the template. Detach the project first to change the list.

<Note>
  Changing the types of a project needs **Manage project settings**. Before this change the right **Manage custom fields** was enough. Give the right to the people who should keep changing the list.
</Note>
