In the traditional approach, Implementation builds and tests the product or system and prepares everything needed to keep the deployment risks low.

## What happens in Implementation

- The product or system is developed or, if it was procured, configured and adapted.
- The organization is put into effect.
- In IT projects, the system is integrated into the operating infrastructure.
- The **preliminary acceptance** is carried out.
- The operating organization is set up and the documentation is prepared.
- Deployment is prepared on the basis of the deployment concept.
- Depending on the scenario, tests are carried out and the migration is prepared.

## How Implementation ends

The **phase release** decision for Deployment is taken. It is based on the preliminary acceptance decision. The deployment risks must be assessed and acceptable; otherwise deployment cannot go ahead.

## In Collabase

- Track the development or configuration work on the [Board](/projects/board) or in [Sprints](/projects/sprints), linked to the requirement tasks from Concept.
- Run the tests in [Test Management](/test-management/test-runs) and link the runs to a **Preliminary acceptance** [milestone](/test-management/milestones). Its aggregate pass rate supports the decision.
- Write the user manual and operating manual in [Collabase Docs](/docs/pages).
