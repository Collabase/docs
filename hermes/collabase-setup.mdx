Every Collabase installation comes with two HERMES project templates. They bring the phases, gates, work item types and workflows a HERMES project needs, so you do not have to build them yourself. As an administrator you decide which templates are offered. Project managers then create each HERMES project from one of them.

| HERMES element | In Collabase |
|---|---|
| **Project** | A project in a Space, created from a HERMES template |
| **Approach** | The system template **HERMES klassisch** or **HERMES agil** |
| **Phase** | A phase on the project's **Phases** tab, shown as a band on the project timeline |
| **Milestone** | A milestone of a phase. The gate at the end of each phase records the decision. |
| **Work package** | A work item of the type **Arbeitspaket** |
| **Task** | A work item of the type **Aufgabe**, under its work package |
| **Status report** | The monthly status report on the project's **Reports** tab |
| **Portfolio** | The **Portfolios** page |
| **Risk list** | The risk register of the Space |
| **Roles** | [Groups and Space roles](/concepts/permissions), see [Roles](/hermes/roles) |

## What every installation brings

Two system project templates exist on every installation from the start:

| Template | Use |
|---|---|
| **HERMES klassisch** | Projects that follow the classical HERMES approach |
| **HERMES agil** | Projects that follow the agile HERMES approach |

Each template brings phases with gates and milestones, and two work item types:

| Work item type | Use | Fields |
|---|---|---|
| **Arbeitspaket** | The default type. One work item per work package. | **Ziel**, **Auftrag**, **Erwartetes Ergebnis**, **Vorgaben**, **Abgrenzung** |
| **Aufgabe** | A plain task for the work under a work package | None beyond the standard fields |

### Workflow «HERMES Arbeitspaket»

Statuses: **Vorhabenidee** → **Analyse** → **Bereit** → **Umsetzung** → **Fertig**, plus **Sistiert** for work packages on hold.

Transitions: **Analyse starten**, **Freigeben**, **Zurück zur Idee**, **Umsetzung starten**, **Zurück zur Analyse**, **Abschliessen**, **Wieder eröffnen**, **Sistieren** (from any status) and **Wieder aufnehmen**.

### Workflow «HERMES Aufgabe»

Statuses: **Offen** → **In Arbeit** → **Erledigt**, plus **Verworfen** for tasks that are dropped.

Transitions: **Starten**, **Zurückstellen**, **Erledigen**, **Wieder öffnen**, **Verwerfen** (from any status) and **Wieder aufnehmen**.

System workflows and system work item types show a lock icon and cannot be deleted. You can still adjust their statuses and transitions in the workflow editor under **Administration → Workflows**. See [Workflows](/projects/workflows).

## Choose which templates are offered

<Steps>
  <Step title="Open the project templates">
    Go to **Administration → Project Templates**. The page has two sections: **System templates** and **Your templates**.
  </Step>
  <Step title="Switch the system templates on or off">
    System templates cannot be edited or deleted. Their switch decides whether they are offered when someone creates a project. Switch off the HERMES template you do not use.
  </Step>
  <Step title="Add your own templates if needed">
    Templates you create appear under **Your templates**. See [Project templates](/projects/templates).
  </Step>
</Steps>

## Start a HERMES project

<Steps>
  <Step title="Create the project">
    In the Space, create a new project and choose **HERMES klassisch** or **HERMES agil**. The project starts with the phases, gates and milestones of the template.
  </Step>
  <Step title="Plan the work packages">
    Create a work item of the type **Arbeitspaket** for each work package and fill in its fields. Add **Aufgabe** work items under a work package for the work it contains.
  </Step>
  <Step title="Fill the roles">
    Add the members and groups to the project. See [Roles](/hermes/roles).
  </Step>
</Steps>

### Existing projects

A project that was not created from a HERMES template can take over the phase model later. Open the project's **Phases** tab and choose **Import phase model**. Phases the project already has stay first.

## Phases and gates

Each phase ends with a gate. When the gate decision is recorded, the project moves to the next phase. The project status follows the phases, so you do not set it by hand.

On the project timeline, each phase is shown as a band with a gate marker at its end. See [Phases](/hermes/phases) and [Milestones and decisions](/hermes/milestones).

## Monthly status reports

Project managers write a status report each month on the project's **Reports** tab under **Status report**.

- **One overall traffic light** shows the state of the project.
- **Review.** The project manager submits the report for review. It is then approved, or returned for changes. When it is approved, the project sponsor is notified.
- **Management attention.** Mark the report when the project needs a decision or support from management. A reason is mandatory.

## Portfolio

The **Portfolios** page shows all projects of a portfolio in one table:

| Column | What it shows |
|---|---|
| **Status** | The project status |
| **Phase** | The current phase |
| **Traffic light** | The traffic light of the latest approved status report |
| **Needs management** | Set when the latest report asks for management attention. Hover to see the reason. |
| **Next milestone** | The next open milestone |
| **Risks** | Open and critical risks |
| **Budget used** | The share of the budget already spent |

Filter by portfolio, including its sub-portfolios, or show **Needs management only**.

The person responsible for a portfolio can edit it and everything below it. Only someone who manages the parent portfolio can hand a portfolio to another owner. The top level is managed by administrators.

## Risks

The risk register of a Space lists the risks of its projects. A risk can name the project it belongs to and a measure. The measure is a work item: search for it and pick it, and the risk links to it. Filter the register by project or show critical risks only.

## Costs and budget

- **Budget warning.** When 80 % of a project's budget is used, a banner appears on the project home and on the **Costs** tab. People with the budget permission get a notification, at most once per month. To switch the notification off, turn off the event `budget-warning` under **Administration → Mail Templates**.
- **Budget changes** need the budget permission.
- **One-off costs** are either **planned** or **incurred**. Only incurred costs count as spent.
- **Cost dashboard.** Filter by Space, portfolio and cost type. The dashboard shows planned costs and effort as plan, actual and remaining.

## Web links and attachments

Projects and work items can carry web links, for example to the official HERMES documents your organization keeps elsewhere. A project link marked **Pass to new work items** is copied to every new work item of the project. Sub-items inherit the links of their parent.

Attachments can be switched off where files must not be stored in Collabase:

- **For the whole instance:** **Administration → Search Index**, card **Attachments on work items**. Existing files stay readable.
- **For one project:** **Project settings → Apps → Attachments**.

## Meetings from a work item

To discuss a work package, open the work item, go to the **Meetings** panel and click **Create meeting**. Collabase fills in the title, project and Space, links the work item on an agenda point and proposes the assignee and the project members as participants. Deselect anyone who does not need to attend. See [Meetings](/meetings/overview).

## Private projects

A project can be private. Only its members, the owner of the Space and administrators see a private project and its work items. This applies everywhere: lists, search, links and reports.
