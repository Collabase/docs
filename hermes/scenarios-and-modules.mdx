Projects differ in content and complexity. HERMES handles this with **scenarios**: each scenario contains the method elements that matter for one type of project. The scenario is chosen in Initiation, together with the solution variant, and covers the phases between Initiation and Closure.

## Standard scenarios

| Scenario | For projects that |
|---|---|
| **Service/product development** | Develop a new service or product |
| **Service/product adaptation** | Adapt an existing service or product |
| **IT development** | Develop a new IT system |
| **IT adaptation** | Adapt an existing IT system, for example a procured standard product |
| **Organizational adjustment** | Change the organization, its processes or structures |

The list is not final. The Federal Chancellery reviews demand for new scenarios periodically.

## User-defined scenarios

Organizations can adapt the standard scenarios to their needs and create **user-defined scenarios**. HERMES online also offers sizing, which fits the documentation effort to the size and complexity of the project.

## Modules

Modules are reusable building blocks assigned to phases. A module groups outcomes that belong together, with the tasks that produce them.

| Group | Modules |
|---|---|
| **Steering and management** | Project steering, Project management |
| **Execution** | Project foundations, Procurement, Organization, Product, IT system, Tests, Deployment organization, IT migration, IT operation, ISDP |

ISDP stands for information security and data protection.

To meet the requirements of project governance, four modules are mandatory in every project: **Project steering**, **Project management**, **Project foundations** and **Deployment organization**. Project managers can create additional modules and use them in user-defined scenarios.

## In Collabase

A scenario maps well to a project template. Create one template per scenario your organization uses, for example **HERMES IT development** and **HERMES Organizational adjustment**. Each template bundles:

| Template component | HERMES content |
|---|---|
| **Workflow** | The statuses for outcomes and milestones |
| **Task types** | Phase, Outcome, Milestone and, for agile, Requirement |
| **Field collections** | Fields such as HERMES phase, module and responsible role |
| **Views** | Roadmap, Board, Backlog and Sprints for agile, Docs, Reports |

See [Project templates](/projects/templates) and [Set up HERMES in Collabase](/hermes/collabase-setup).
